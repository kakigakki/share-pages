0为什么要做

两个都会发生的场景 场景 A：三年后你想找「京都那碗拉面」的那段。翻出移动硬盘，看到 DSC_0412.MP4 到 DSC_1893.MP4，只能一个个点开看。找了半小时放弃了。
场景 B：硬盘掉在地上，或者某天插上去提示「需要格式化」。三年的旅行素材一次归零。
这一页就是为了这两件事。

成本对比

做不做
时间成本每次旅行 10 分钟0
三年后找一段素材10 秒半小时，或者放弃
硬盘坏了从备份恢复全没了
想重剪旧片子直接开工工程找不到、素材路径全断
一条基本判断 硬盘比你的时间便宜得多。不要为了省几百块的存储空间去删原始素材——你以后重剪一次省下的时间就值回来了。
真正该省的是找东西的时间，而那靠的是命名和索引，不是删文件。

1文件夹结构

一次旅行一个文件夹，里面结构固定。固定的好处是不用每次想，而且脚本和批处理能直接套用。

2026-08_京都/
├── 01_原片/          ← 相机/手机直接导出来的，只读，永不修改
│   ├── camera/
│   └── phone/
├── 02_代理/          ← ffmpeg 转的 1080p，剪辑时实际用的
├── 03_音频/          ← 环境音、音效、口播、旁白
├── 04_音乐/          ← 用到的曲子 + 授权记录
├── 05_工程/          ← 剪映草稿备份、LUT、字幕文件
├── 06_导出/          ← 成片（各版本）
│   ├── 京都_v1_横屏.mp4
│   └── 京都_v1_竖屏.mp4
├── INDEX.md          ← 可检索索引（见第 5 节）
└── README.md         ← 这趟旅行的一句话说明 + 拍摄设备 + 参数
最重要的一条规矩 01_原片 是只读的，永远不改、不删、不重命名里面的文件。
所有操作都在 02_代理 上做。原片就当成底片——底片不能改，改坏了没有第二份。

顶层怎么放

D:/Video/
├── 2026-08_京都/
├── 2026-09_蓼科ドライブ/
├── 2025-11_台湾/
├── _素材库/           ← 跨旅行复用：LUT、音效、片头片尾、模板
└── _INDEX_ALL.md      ← 所有旅行的总索引

下划线开头的文件夹会排在最前面，一眼能看到。

2命名规则

命名的唯一目标 让「按名字排序」= 「按时间排序」，并且看名字就知道是什么。
做到这两点，你就再也不用点开文件确认了。

三条硬规矩

01日期一律用 YYYY-MM-DD

唯一能让字母排序 = 时间排序的格式。2026-08-15 会自动排在 2026-09-01 前面；写成 8月15日 或 15-08-2026 就全乱了。

02不要用空格，用下划线或连字符

空格会让命令行、脚本、ffmpeg 批处理全部出问题（要不停加引号转义）。用 _ 分隔大块，- 分隔小块。

03版本号用 v1 v2 v3，不要用「最终」

最终版_真的最终_改3.mp4 是所有人都犯过的错。数字永远单调递增，永远不会歧义。

成片命名

2026-08_京都_v2_横屏_1080p.mp4
2026-08_京都_v2_竖屏_1080p.mp4
└─日期─┘└地点┘└版本┘└画幅┘└分辨率┘

要不要重命名原始片段

不建议。相机自己的编号（DSC_0412）是唯一且连续的，改了反而容易和备份对不上、和索引对不上。
正确做法是：文件名保持不动，靠索引文件建立「文件名 → 内容」的映射。见第 5 节。

3回来当天：10 分钟

旅行结束当天做，别拖——拖过三天你就再也想不起来哪段是哪了。

1 · 2分
建文件夹，导原片
按第 1 节的结构建好，把卡里的东西整卡复制进 01_原片。别挑，全导。
2 · 1分
立刻做第二份备份
在删卡之前。第二份放在另一块物理硬盘上。
见 第 4 节。
顺序很重要：备份完成之前不要格式化存储卡。卡是你此刻的第二份副本。
3 · 3分
写 README
三行就够：这趟去了哪、用了什么设备、有什么特殊情况（比如"第二天下雨"、"手机素材偏冷"）。
三年后这三行比什么都有用。
4 · 4分
挂上代理转码，然后去睡觉
跑 ffmpeg 批量转 1080p，让它自己跑。明天起来就能直接开剪。

4备份策略

3-2-1 原则 3 份副本 · 2 种不同介质 · 1 份异地。
听起来夸张，但对旅行素材来说，做到「2 份 + 1 份异地」就已经覆盖了绝大多数风险。

实际怎么落地

层级放哪防的是什么优先级
第 1 份电脑本机硬盘 / 工作盘—（这是工作副本）必须
第 2 份另一块物理硬盘（移动硬盘）硬盘故障、误删必须
第 3 份云盘 / NAS / 放在别处的硬盘失窃、火灾、进水强烈建议
不算备份的几种情况 · 同一块硬盘上复制两份 —— 硬盘坏了两份一起没
· 同一台电脑的两个分区 —— 同上
· RAID —— RAID 防的是硬盘故障，不防误删和误格式化，它不是备份
· 只留在存储卡里 —— 卡是消耗品，而且你迟早要格式化它

取舍：不是所有东西都要三份

内容备份级别理由
01_原片3 份唯一不可再生的东西
03_音频（现场录的）3 份同样不可再生
05_工程 + INDEX3 份体积极小，但重做要几小时
06_导出成片2 份有原片和工程就能重做
02_代理0 份随时能重新转，不用备份。它占的空间最大
最容易被忽略的一项 剪映草稿要单独备份。它默认在系统盘的某个目录里，不在你的项目文件夹中——重装系统就没了。
剪完之后把草稿文件夹整个复制一份到 05_工程/。体积很小，但省掉的是几小时重剪。

一条同步命令

Windows 用 robocopy 做增量同步（只复制变化的部分）：

robocopy "D:\Video\2026-08_京都" "E:\Backup\2026-08_京都" /MIR /XD 02_代理 /R:2 /W:5
/MIR镜像同步（源删了目标也删）
/XD 02_代理排除代理目录，不浪费空间
/R:2 /W:5失败重试 2 次、间隔 5 秒，避免卡死

/MIR 会删除目标里源已经没有的文件——第一次跑之前先确认路径没写错，或者先去掉 /MIR 试一次。

5可检索索引

这一节是整页最有价值的部分 成片会过时，索引不会。
一条 3 分钟的成片只用掉素材的 5%。剩下 95% 如果没有索引，等于不存在——建了索引，那 95% 才真正属于你。

最省事的版本：一个 markdown 文件

剪辑时你本来就要过一遍素材记时间码（粗筛那一步）。把那份记录顺手存下来，就是索引——等于零额外成本。

为什么用 markdown 而不是 Excel markdown 是纯文本，能被全局搜索工具直接搜到内容。在 Everything、VS Code 或系统搜索里搜「拉面」，能直接命中这一行。
Excel 是二进制，多数搜索工具搜不到里面的文字。

6自动打标（可选，工程量大）

如果素材已经多到手写索引也来不及，可以让机器先过一遍。但先说清楚：手写索引对绝大多数人已经够用了，下面这套是给"素材几个 T、且愿意写点脚本"的情况准备的。

1
场景切分
PySceneDetect 把长片段按镜头切开，输出每个镜头的时间码。
2
抽关键帧
每个镜头抽 1–3 帧存成 jpg。按镜头抽，不要按秒抽——几千帧的成本没必要。
3
质量打分（纯 CV，零成本）
拉普拉斯方差判虚焦、直方图判过曝欠曝、pHash 找重复镜头。这一步能直接毙掉一半废片，而且不用任何模型。
4
视觉打标
把关键帧喂给本地 VLM（Mac 上 mlx-vlm 跑 Qwen-VL 即可），生成一句话描述和标签，写进 JSON。
5
生成 INDEX.md
把 JSON 渲染成和第 5 节一样格式的 markdown，汇入同一套搜索体系。
更省事的现成方案 Immich（开源自建相册）内置 CLIP 语义搜索，可以直接搜「日落 海边 空镜」找自己的素材，照片视频都支持。
不想写脚本又想要语义搜索的话，这是最短路径。

7该删什么，不该删什么

内容理由
可以删代理文件（02_代理）随时能重转，而且占空间最大
可以删误触的 1 秒片段、纯黑、拍到地面的确定无用
可以删同一镜头拍了 3 遍里明显失败的但只删明显失败的，"还行"的都留着
可以删中间导出的测试版本只留最终版和上一版
不要删原始素材不可再生。硬盘比你的时间便宜
不要删当时觉得没用的空镜下次做别的片子可能正好要
不要删剪映草稿工程体积极小，重做要几小时
不要删现场录的环境音不可再生，而且以后能复用
删素材前问自己一句 「这个能重新拍到吗？」
不能 → 不删。能 → 随便。
旅行素材几乎全部属于"不能"这一类，所以默认答案是不删。真的空间紧张，就去买硬盘，不要删底片。

8长期保存

01移动硬盘每年通电一次

长期不通电的机械硬盘有停摆和磁性衰减的风险。每年插上跑一次同步，顺便验证还能读。

02别把 SSD 当冷备份

SSD 长期断电存放有数据衰减风险，不适合"放进抽屉五年不管"。冷备份用机械硬盘，或者上云。

03硬盘用三五年就该换

不是坏了才换。在它坏之前迁移到新盘，成本远低于数据恢复。

04存 H.264/H.265 就够

不用为了"归档质量"转成 ProRes——体积会大到离谱。相机原生的格式就是最好的归档格式。

05每次备份后随机抽查一个文件

没验证过的备份不算备份。随手打开一个视频确认能播，10 秒的事。

9流程清单

旅行回来当天（10 分钟）

  • 建好文件夹结构
  • 整卡导入 01_原片，不挑不删
  • 做第二份备份 —— 在格式化存储卡之前
  • 写 README（去了哪 / 什么设备 / 特殊情况）
  • 挂上 ffmpeg 代理转码，去睡觉

剪辑时（顺手做，零额外成本）

  • 粗筛记的时间码，直接存成 INDEX.md
  • 音乐的曲名 / 来源 / 许可证记进 04_音乐/
  • 调色参数记一笔（下次同一趟旅行的续集能直接复用）

成片导出后（5 分钟）

  • 成片按规范命名，放进 06_导出
  • 剪映草稿复制到 05_工程/（它默认不在项目文件夹里）
  • 删掉 02_代理 释放空间
  • 跑一次 robocopy 同步到备份盘
  • 在 _INDEX_ALL.md 加一行
  • 随机打开一个备份文件确认能播

每年一次

  • 所有移动硬盘通电一次，跑同步
  • 检查 _INDEX_ALL.md 里标了 ⚠️ 的异地备份补上
  • 用了三五年的硬盘考虑迁移到新盘
如果只做三件事 ① 回来当天做第二份备份（在格式化卡之前）
② 粗筛的时间码顺手存成 INDEX.md
③ 剪映草稿复制到项目文件夹里
这三条加起来不到 5 分钟，覆盖了 90% 的风险和 90% 的"以后找不到"。
